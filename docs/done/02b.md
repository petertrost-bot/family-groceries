## Brief items

1. **Household join from the menu.** Job 4 fixed the crash in #5 (the dialog
   owns its controller). I checked the other dialogs in `app/lib`: every
   controller lives in a `State` and is disposed in `dispose()`, so none
   has the same pattern. 04's widget test fails on the old dialog with both
   messages ("A TextEditingController was used after being disposed",
   `'_dependents.isEmpty'`) and passes on main. New e2e test
   (`live-sync.spec.ts`, "a member of another household joins with a code
   from the menu"): the second user leaves their own household, sees the
   new list, the old list is gone, both share adds, the list is online and
   there are no console errors. Note: the release web build strips Flutter's
   debug asserts, so it never showed the crash. Only the widget test and the
   debug app can show that. On the Linux debug app (fg, Xvfb, Marionette) the
   hh-join-menu recipe works and `fg logs --grep EXCEPTION` is empty
   (`docs/screenshots/job-2b/fg-*`).
2. **Dictionary.** I swept 345 common non-food items through `classify_item`
   on the local stack. Misses included Mülltüten, Spültabs,
   Ohrenstäbchen and Taschentuch. Some were wrong matches: Sekundenkleber →
   Fleisch (via "leber"), Bratschlauch → Obst (via "lauch"), Blend-a-med →
   Fleisch, Butterbrottüten → Kühlregal. New migration
   `20261023074045_classifier_dictionary_household.sql` (1159 terms,
   generated). 58 new rows in `supabase/tests/classifier_dictionary.test.sql`.
   They fail on the old dictionary and pass on the new one. DECISIONS 2b.1.
   The sweep itself is checked in: `supabase/classifier/sweep.tsv` lists
   the 345 items with their category, and `supabase/classifier/sweep.sh`
   reruns it on the local stack and prints what moved. CI and `verify.sh`
   run it (DECISIONS 2b.12). Its first rerun found Babytücher and "Feuchte
   Tücher" in Haushalt next to Feuchttücher in Drogerie. Both are Drogerie
   now, and two pgTAP rows (failing first) guard them.
3. **Classifier tests run from their folder.** `supabase/classifier/deno.json`
   (+ lock). CI and `verify.sh` run `deno fmt --check && deno lint && deno
   test --allow-read` inside it.
4. **dm screenshot.** The grey Edeka chip was not hover. The screenshot
   caught the chip's deselect animation; dm was mid fade-in in the same frame.
   I measured this with timed screenshots: the colors settle within 150 ms.
   `screenshot()` now waits for two identical frames. The store shots in
   `job-2/` and `job-4/` are retaken. Chip styling: the selected chip is
   light green and the others are outlined.
5. **OAuth e2e flake.** 03b did not touch it. The cause was load from leaked
   browser contexts. Specs open a context per user and never closed it, so
   one worker kept every earlier test's app alive: 48 renderers and 9.4 GB
   of RSS by the end of one run. In a failed run, the deny-consent test's
   first click waited 34 s for its page to load. `e2e/tests/fixtures.ts`
   closes them, and `conventions.spec.ts` keeps every spec on it. Peak is
   now 3 renderers and about 750 MB. mcp.spec's `retries: 1` is removed.

## Found on the way (all fixed, each with a failing test first)

- **Offline after creating or joining a household.** Two overlapping
  resyncs shared one ack map. One threw, and the list showed Offline until
  the next write: 3/3 on the web build, 2/3 creates on the Linux app.
  Fixed in `list_cubit.dart` (DECISIONS 2b.4).
- **Offline cold start took 15 s to say so.** postgrest 2.9.1 retries each GET
  three times (1+2+4 s). The app turns that off and reads through
  `client.rest`, because `client.from` ignores the option. The cached list
  now shows in 0.7 s instead of 7.7 s, and the indicator in 0.7 s instead
  of 15 s (DECISIONS 2b.5).
- **Catalog reload undid concurrent changes.** It read `state` before
  awaiting the fetch. An add acked meanwhile stayed "pending" forever
  (DECISIONS 2b.7).
- **Blank page after a network change during load.** Chromium aborts loads
  with `ERR_NETWORK_CHANGED`. `app/web/flutter_bootstrap.js` reloads, at
  most twice (DECISIONS 2b.8).
- **Changes lost before Realtime was live.** The channel join is confirmed
  before the server's Postgres listener runs. The list now resyncs on the
  "Subscribed to PostgreSQL" system event too. A new e2e test holds that
  message back and inserts in the window (fails before, passes after;
  DECISIONS 2b.9).
- **Offline for good after the server closed the channel** (review 0).
  `realtime_client` never rejoins a channel the server closed (`phx_close`).
  The list now resubscribes while the channel is down (3 s, doubling to 30
  s). Two e2e tests inject a channel close and a socket drop and expect the
  list back online with live updates. The channel case failed every time
  before the fix (DECISIONS 2b.10).
- **"Schokokarte" was Haushalt** (review 0). A generic `karte` term
  caught it. Cards are now listed one by one (Geburtstags-, Glückwunsch-,
  Geschenk-, Guthabenkarte), Chipstüte is sweets and Spüli is Haushalt
  (DECISIONS 2b.11).
- **list.spec read the groups once**, while the last add still sat under
  "Wird einsortiert …". It now polls.
